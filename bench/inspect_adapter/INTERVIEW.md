## 一分钟项目介绍

> 我原来做了基因组注释流程的 Skill，整理了拟南芥、线虫和酵母的真实产物与失败经验。后来把它做成 QC 评测题库，比较规则、裸模型和模型加知识包。为了学习成熟的评测框架，我先复现 Inspect 官方工具和推理任务，再把已有数据、评分与只读生信工具接到它的 Task 接口。现在既能离线回放历史结果，也完成了小规模真实工具试跑，并保留引用错位、处置错误和超时恢复的记录。

如果被问“为什么需要这个项目”，先说明实际问题：统计异常可能来自质量下降，也可能来自文件 ID 连接或配置错误，需要结合证据决定是回退重做还是先修输入。仅输出一个看似合理的答案，不够支撑下一阶段工作。

## 面试追问

**Inspect 提供什么，你写了什么？**

Inspect 提供评测编排、模型接口、工具消息循环、评分接口和日志。项目提供基因组 QC 题目、历史数据适配、处置合同、五个只读工具、领域评分接入及一致性和失败核验。历史汇总复用了旧计分函数，所以只能说迁移一致，不能说两套独立计分器交叉证明正确。

**如何避免答案泄漏？**

公开消息和工具数据只来自 task 与 artifacts。答案进入私有评分 target，不作为模型消息；工具在加载时将公开白名单读成不可变字节，不接受任意磁盘路径。绝对路径、上级目录和非白名单文件被拒绝。这是受限工具接口，不能称为任意代码执行沙箱。

**为什么不只让模型直接输出 JSON？**

原开发试跑有格式失败。第二版把工具收集与最终提交分开：前者保留原生工具协议，后者关闭工具并使用 JSON object 输出。它改善了这四题的格式完成情况，但提示与输出配置等多项因素同时变化，且已经看过旧结果，不能声称是独立测试上的因果增益。

**怎样证明数值没瞎算？**

工具由 Python 在完整的公开序列/表格字节上计算，读取分页不影响计算输入。保留参数和结果，离线核验10次计算能重现。数值正确仍不保证引用支持结论或下一步处置正确。

**一个成功案例和一个失败案例是什么？**

dev_003 的区间统计与正常软屏蔽审核最终 pass 一致。dev_001 的2/32统计正确，但引用行错位，最终 block 没有匹配冻结的 rollback。沿 [工具课程](TOOL_LESSON.md) 和 [原诊断](audit/pilot2/DETAILS.md) 查看原始结果；没有因为解释得通就修改答案或修分。

**如何处理接口失败和预算？**

失败保留在计划分母里。官方小规模首轮提前停止后，固定只恢复7个未完成槽位，原成功结果保持；恢复继承已有请求预留，累计26/32次。两次无响应仍计调用额度，未知用量与收费如实记录。没有无限重试或重新设置额度。

**能说明整体准确率或 Skill 有效吗？**

历史静态 A/B/C 结论只按其冻结题目与预注册口径报告。新工具试跑四题属于开发集，不能替代 held-out、多模型对照或独立评审。官方问答9/10由同模型评分，也不能当作生信准确率。独立来源的工具测试集才适合后续验证泛化。

## 数字的正确分母

- 24题、648条历史观测：包含条件与重复，不能说648道题；这次是归档回放。
- 四道开发题：真实请求16次、工具25次，决定联合匹配3/4；不能宣传75%生产可靠率。
- 官方12样本：工具2题通过，问答10题得9分，同模型评分；不是复现完整 Inspect 项目。
- 432项全仓测试：包含原项目与新扩展，不是全部由 Inspect 接入新增。

作者AI审查与历史真人编码分开。没有另一位生信专家盲审时，就明确说明没有；不把模型复核改写为真人复核。
