# v3 候选构造计划（未构题、未定答案）

目标暂为 28 道：6 开发 + 4 回归 + 14 封存母题 + 4 压力副本，上限 35。该数量是审核目标，最终 N 在来源适用性检查与审题后确认，不能把私有设计行数或副本数称独立主样本量。

| 分组 | 暂定构造 | 必需证据与停止条件 |
|---|---|---|
| 开发 2 | T1 低覆盖：可确证原因 / 原因资料不足 | 真实逐记录连接与统计分母；找不到确证执行证据时保留 uncertainty 设计，报告已知原因版本缺口 |
| 开发 2 | T1 空证据：正在审核输入 / 已完成交付 | delivery 状态和实际证据消费记录；空 hints 不能单独作为未使用 RNA 的答案 |
| 开发 2 | T1 屏蔽：reference/delivery 角色对照 | 真实屏蔽片段和明确下游契约，不能把局部比例当全基因组 |
| 回归 4 | 旧题正常、ID、基因丢失、低覆盖各一 | 下一阶段先按机制固定具体旧题号，原任务/答案及原成绩保持原样；与 v3 扩展证据评分的报告分开 |
| 封存 14 | 每个已验收 T3 来源一正常、一单一接续/引用变体 | 确定性完整特征块与对应完整 FAA 记录、所有必需上下文；不能截断伪造故障 |
| 压力 4 | 开发的 2 个母题及封存的 2 个母题 | 在确定母题/具体 ID 后冻结，仅加固定催促句，其它内容复用；不加入 H1 主分母 |

封存七来源按 SOURCE_SPLIT_PROPOSAL 的顺序全部纳入适用性检查，模板先在开发来源确定。优先 CDS protein_id → FAA 精确接续；只有完整层级/消费者证据支持才采用 Parent/层级变体。当前尚未读取并选择具体块，不能承诺七来源都可实现同一模板。每个不适用项报告原因；更换模板/排除/改变题数需要版本登记和用户审核，不按模型成绩筛选。

不把七个相同连接机制的不同物种叫七个新机制。pair 中 task 和表面统计相同，正常成员来自原始未修改记录；mutation 只改变合同相关的单一标识/引用。依赖参考序列的完整生物学检查不从 GFF/FAA 推断，缺基因组时不能构造需要该证据的题。

执行顺序：本规格用户确认 → 开发材料与可答性审核 → 完善并锁 C3 通用包/模板/暴露定义 → 封存材料确定性构造 → 独立盲审与分歧解决 → 用户逐题确认、门槛填写 → Windows/Linux 复现 → expected/规格/内容清单冻结 → harness/mock → 新预算批准 → 真实模型与 A。

不提前创建 FROZEN 或伪造审题完成。独立人类审核人未确定时可以准备资料和内部审核，但报告不能称已完成独立验证。所有候选和答案在用户确认前均为 draft。

回归的旧版 verdict/root 标准单列保持原样；v3 扩展证据/不确定性字段只作新审计，不能把旧标签直接称为 v3 已确证原因，也不进入 H1/H3 主分母。构造时须保存旧题与答案的版本/SHA，并明确旧协议分数和新审计各自分母，不回写 v2 文件。
