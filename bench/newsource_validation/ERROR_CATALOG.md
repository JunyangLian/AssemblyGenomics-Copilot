## 演示一：取得证据后仍误报

从 [T3 报告](../inspect_adapter/t3_test/glm_followup1/REPORT.md)找 `tools / t3_005 / r2`，模型对正常材料判 block，称 `XP_311153.4` 不在蛋白文件中。实际完整读取的 FAA 共 55 行、没有下一页，header 就在第 32 行。

演示时先展示公开 GFF 与 FAA，再展示模型原判定，核对第 32 行，并展示工具已读取完整文件的日志摘录。它说明读取成功不保证模型正确使用证据。其他两次重复正确，故题层多数正常；观测层误报保留。

## 演示二：找到错误，却选错根因类别

展示 `tools / t3_004 / r1`：模型指出 mRNA 的 Parent 引用不存在的 gene，并给出针对 Parent 的修复，block 正确；但 root_cause 使用跨文件 `id_mismatch`，未匹配合同中的 `gff_hierarchy_error`。

沿公共合同解释两类别的边界，再查看原输出和严格评分。不要将“发现问题”说成“根因也正确”，也不要为了演示改写原答案。相同模式在另一题出现，来源见原报告。

两段演示使用已公开材料和结果，可以讲解模型判定；完整原生对话保留在作者本地，公开仓库不假称包含全部对话。静态演示不需要 API key，也不产生新测试成绩。
